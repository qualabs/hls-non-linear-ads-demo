About this page: there is no ad server, and which manifest each mode loads

There is no ad presentation server behind this page. The two capabilities travel on every asset-list request, as such a server would read them, and the answer is one static file per break that always carries every option of the ad: video first, then the same campaign as a still image in another layout. What decides what is drawn is the library, in panel 4. With our library the player loads the concurrent manifest; in native mode, the interstitials manifest, and hls.js plays the standard part of the same asset-list. The combination is in the URL.

4 What the library kept

The same answer reaches every device. Each option is checked against what this device declared, and the ones it can show are handed to the renderer in order. If an asset of the one mounted fails to load, the renderer mounts the next, then the linear default.
